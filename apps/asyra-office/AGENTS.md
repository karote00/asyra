# Asyra Office - Persistent Visual Contract

Read the root AGENTS.md and the current
[product plan](../../docs/ai/apps/asyra-office/plans/office-rebuild-plan.md#source-authority).
The owner's reference-first requirement applies to the entire app, all assets,
all rooms and every subsequent task. It does not require renewed reminders.

- Read the approved complete image and the current approved per-part images
  relevant to the task before editing geometry, appearance or placement.
- Later explicit owner corrections control the affected detail. Otherwise, the
  approved reference is the visual authority; numeric specs are construction
  inputs. Correct conflicting dimensions from the reference and synchronize docs.
- Never substitute generic objects, simplify visible geometry/details, or alter
  appearance/proportions/placement for convenience or optimization. Choosing
  procedural code instead of Blender does not lower the visual standard.
- Preserve approved unaffected work. Do not rebuild the whole app merely because
  this contract applies globally; follow the current task's bounded scope.
- Validate item-by-item from the corresponding camera and enlarged crops:
  silhouette, components, details, appearance, proportions, layout and contact.
  Tests/builds alone do not prove visual fidelity.
- Visible differences remain unfinished. State them explicitly; never label
  approximate output as complete or infer approval from tests. Unreadable or
  hidden source details are unresolved, not permission to invent visible details.
- Existing performance gates do not authorize reduced fidelity or relaxed limits.
  Report a concrete conflict when both cannot be satisfied. Keep rejected complex
  assets absent until the owner-approved construction path can reproduce them.
