# Design Domain Knowledge evaluation - 2026-10-18

## Conclusion

The real Design agent can retrieve existing Domain Knowledge and finish editable
work through the normal UI/provider/tool path. Adding selective App guidance
changed observed use: the two original creation briefs and two independent
creation briefs retrieved relevant modules; both known-value editing briefs
completed without an unnecessary knowledge lookup. All checked requirements and
non-target preservation checks passed.

This is evidence of adoption and preserved behavior, **not a demonstrated visual
quality or speed improvement**. The baselines already satisfied their briefs.
No new Knowledge Module is justified by these observations. Existing content,
Runtime retrieval, authorization, drawing tools and the model are unchanged.

## Method and evidence

Base: `3d503aa714336946839374dc948e9c171cfb8182` (merged #346).
The single candidate production change is the Knowledge paragraph in
`apps/asyra-design/server/ai-domain-prompt.ts`. Every run records its exact prompt
hash, shared-content hashes, model `gpt-6-astra`, effort `medium`, isolated document,
complete captured tool I/O and final canonical document. No secondary evaluator
model was used. The evaluator inspected actual browser screenshots at 1440x900,
DPR 1, with the recorded fit zoom. Canonical geometry and property references
provide evidence beyond screenshots.

Three development briefs and three different transfer briefs were frozen in
`apps/asyra-design/test-data/knowledge-evaluation/cases.json` before evaluation.
One valid run per arm/case, no favorable retries. Transfer cases were run only
after the candidate prompt was frozen and were not used to tune it.

The committed compact evidence index is
`apps/asyra-design/test-data/knowledge-evaluation/evidence/2026-10-18.json`.
It includes run IDs, source and artifact hashes, provider stream IDs, actual
call IDs/timings, knowledge inputs/source revisions and preservation results.
Original local artifacts are in `tmp/knowledge-evaluation/<run-id>/` and
`apps/asyra-design/tmp/ai-executions/`; payload contents were read with SHA-256
verification. Raw execution payloads and local service configuration are not
published. Three unmodified comparison screenshots accompany the compact index.

## Knowledge application versus correlation

- Ring: `read_knowledge({ids:["icons"]})` precedes editable vector creation.
  The output follows the module's editable geometry/silhouette advice, but the
  baseline was already correct. No improved geometry claim follows.
- Announcement: selected typography/color/button advice is delivered before
  construction. The final document uses distinct heading/body/action roles,
  aligned margins, navy text on a light surface and one coral action. These
  choices are consistent with the read advice **and** the user's brief; this
  experiment cannot isolate which caused them.
- Independent invitation: reads colors/typography, then produces cream text and
  a dominant serif heading on dark green with one gold accent. No unrelated
  landing-page or docs-page specialization is loaded.
- Exact edits: no knowledge lookup; canonical snapshots prove preservation.
  Optional advice did not become an execution prerequisite.

Candidate knowledge discover/read owner spans total approximately 2.4-4.9 ms per
creation request. This does not measure the model's extra decision/token cost.
Some candidate runs took longer than baseline; one sample cannot attribute this
to guidance or establish a latency regression/improvement. There is no speed claim.

## Root-cause classification and decisions

| Layer                  | Evidence                                                                                                            | Decision                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Availability/retrieval | Separate prompted diagnostic discovered general metadata and read colors/button/typography successfully in 43.429 s | Existing access works; no new infrastructure                                     |
| App guidance           | Baseline prompt contains no Knowledge instructions; all three baselines skip it; prompted diagnostic succeeds       | Add selective metadata-first guidance through the existing App prompt            |
| Agent decisions        | Candidate selects small relevant subsets; known-value edits skip lookup                                             | Preserve agent judgment, not a required call count                               |
| Content                | No observed incorrect principle or missing principle causing a failure                                              | Do not add geometry/editing modules merely to cover category labels              |
| App capability         | All frozen outcomes and preservation checks pass                                                                    | No renderer, transaction, persistence or tool behavior change                    |
| Task setup             | Task-context path admission omitted the new independent knowledge owner                                             | Extend existing path allowlist with traversal regression; no new owner machinery |

A successful read does not prove that the model used every principle. No hidden
reasoning is inferred from elapsed time, a final message or a tool success flag.

## Excluded runs and limitations

One composition pilot was interrupted by Vite reload after evaluation-source
files were edited during inference. Two precision fixture attempts failed before
inference with an empty workspace parent before fixture mutation. These are retained harness failures,
not model outcomes. The runner now waits for initial network settling, uses the
formal browser tests' public import route and treats unexpected navigation after
Send as failure. Source stayed frozen throughout all candidate/transfer runs.

The explicitly prompted diagnostic is separate from spontaneous-use results.
All calls use actual inference; no mocked model success is counted. This is a
small, unblinded observational evaluation of simple briefs, not broad proof for
complex illustrations, arbitrary geometry, accessibility compliance, every user
style or repeated-run reliability. Existing deterministic tests protect scoped
retrieval, advisory trust, override composition, context reset and read-only
provider integration; live-model outcomes are never CI assertions.

## Validation

Formal prompt regression failed before the guidance change and passed afterward.
The normal provider integration verifies actual instruction delivery plus existing
knowledge retrieval, context reset and no document writes. The deterministic
manual-evaluation analyzer is included in Design's existing local test command;
real-provider execution remains opt-in. Final delivery checks and their evidence
are recorded in the plan and PR description.
