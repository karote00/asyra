# Flow Inspector Local Agent Execution

## Activation and bounded completion

On 2026-09-08 the user activates Phase 5 local, isolated execution independently
of deferred GitHub enforcement. PR #166 merged as `c820a3bd1`. This supersedes
only the Phase 5 entry dependency; the original Phase 4 mandatory-CI DoD,
independent verifier/issuer and remote refusal/recovery requirements remain open.
Phase 6, merge, publication, deployment and protection changes are excluded.

The first supported task selects one of the three admitted Factory owner steps,
its complete architecture contract and all six retained obligations. Mutations
are a nonempty explicit list of existing `.ts` runtime files within that step's
implementation boundary. Tests, configuration, mapping, package metadata,
control-plane code and accepted histories are never candidate-write capabilities.
No new package or tool is required. Source-writing execution requires macOS's
existing OS sandbox; unavailable containment fails closed.

The reproducible demonstration adapter is deterministic, not a language model.
A real provider requires a separately selected, authorized integration and actual
backend evidence before it can be claimed supported. Missing credentials,
unknown charges or unmeasured token usage cannot silently activate one.

## Task admission

A request binds UUID, actor, target/step, objective, explicit allowed files,
accepted contract digest and revision, captured source identity, adapter identity,
required all-flow validation, wall-clock/tool-call/attempt limits and stop policy.
The admitted step retains inputs, outputs, conditions, bypasses, contributors,
failure owner and adjacent routes. Unknown or incomplete contracts, empty scope,
symlinks, traversal, non-runtime paths, unsupported adapters and hard token/cost
requirements reject before execution. Only the local human action capability may
create, resume, cancel, stop, revoke or hand off a task. Agent outputs are data,
never authorization. One active proof or task is permitted per service.

Names and format-1 task records are tool-owned, brand-neutral wire identities;
existing proof attempt formats and accepted mapping versions remain unchanged.
Task identity replay returns the same task; conflicting input is rejected.
Resuming uses the same task and cumulative budgets, with a fresh attempt UUID.

## Controlled execution

Adapters return JSON operations to a broker: read an admitted source file,
replace exactly one literal in an allowed candidate file using its current digest,
or finish. No shell, process, network, secret, acceptance or delivery tool exists.
Unsupported operations are denied before effects. Adapter output is capped;
files and replacement strings are bounded. Symlinks and noncanonical paths are
rejected before every access. Only task-owned candidate copies can change.
Registered adapters are trusted integration code; their model/tool responses are
untrusted data. An arbitrary executable or plugin is not an adapter registration.

The initial demo selects repair, regression, scope violation, tool limit, stall
or cancellation cases. The repair demonstration makes a harmless source comment
change through the same generic replace operation; regression changes the real
inverse restoration expression and must fail real Factory assertions. Recovery
repairs that same expression. These fixtures prove control-plane behavior, not
AI reasoning or arbitrary development competence.

Each operation is charged before admission, including denials and failed calls.
Elapsed execution milliseconds and attempts accumulate across resume/restart;
active interrupted time is conservatively charged up to the reserved deadline.
There is one active task, bounded elapsed time, calls, attempts, source bytes and
output bytes. CPU and peak-memory hard limits are unsupported. Token and cost usage remain `unknown`; requiring hard enforcement
of either refuses admission. Idle/stalled adapters time out. Repeated identical
edits do not count as progress. Progress is an actual changed source digest or
completed verification, not an adapter's finish assertion. Retry never resets
budgets. Cancellation aborts active verification, waits for owned process
settlement, and preserves partial candidate data. Stop and handoff also preserve
it; revocation permanently prevents further agent operations on that task.

Format-1 task state and audit are persisted together atomically. Restart obtains
the service's exclusive store ownership, marks running tasks interrupted and
never resumes automatically. On resume, recheck current capability, accepted
revision and captured source manifest; stale input blocks execution. Each attempt
and its evidence remain historical. Human handoff contains the same contract,
remaining budgets, source changes, verification and unresolved blockers.
No candidate is applied to the user's checkout automatically.

## Candidate verification

After adapter finish with actual source progress, freeze candidate bytes and
verify a new snapshot against the admitted original tests/configuration and all
six obligations using the existing evidence assessor. The OS sandbox permits
reads only of that snapshot, installed dependencies, the trusted runner and
necessary system runtime files and ancestor package metadata (directory
metadata/listings are not hidden); writes only to that verification attempt's
scratch area; network and all child-process creation are denied. No ambient
credentials are inherited. One sandboxed Node process runs Vitest with a single
worker thread and Node 24 native TypeScript transformation; it cannot fork or
detach a successor. A watchdog binds the process to its service parent and the
existing deadline/process-group cleanup. The generated readonly bootstrap and
configuration are included in source and configuration fingerprints. Candidate source is untrusted even during
verification. Verification artifacts outside the candidate process's authority
bind task, attempt, actor, accepted revision, baseline and candidate manifests.
The verifier rechecks frozen source after settlement. This is not an
independently protected verifier: candidate runtime and assertions execute in a
local test process, so arbitrary hostile JavaScript evidence forgery is not
claimed prevented. Human review remains mandatory; the deferred independent
verifier and issuer requirements remain open.

A successful run means execution finished; verification can independently be
passed, failed or unknown. Work is `needs-review` only with complete passing
all-flow evidence and actual source progress, otherwise incomplete. Delivery is
always `not-delivered`. Agent output cannot accept a mapping, retire an obligation,
merge, publish or establish a protected baseline. Potential consumers are all
supported flows sharing the step; confirmed failures come only from assertions.
A human can inspect source changes, retained report and audit before applying
anything through their ordinary review workflow.

## Shared surfaces and work lifetime

The existing service exposes the same task actions and records to CLI, API and
the selected original step card. The detail panel shows scope, adapter fidelity,
execution, work, verification, delivery, budgets, changes, artifacts and handoff.
Original canvas/cards/edges/navigation/zoom remain owned by the viewer.
Unsupported targets have no delegation action; task selection never grants a
verification badge from candidate evidence to the accepted source.

Admission captures source once. Operations update one task-owned retained record;
reads of already admitted state do no filesystem capture, history scan, evidence
assessment or graph replacement. Source is revalidated only at resume and the
verification boundary. No computation cache is introduced. Permanent tests count
capture/operation work alongside immutable record and invalidation correctness.

## Cases and bounded DoD

Formal tests cover valid and invalid admission, unknown tokens, exact step/file
binding, traversal/symlink escape, command/network/secret/acceptance denial,
actual candidate edits, digest conflicts, unchanged edits, output and call limits,
cancellation, elapsed timeout, retry/replay, cumulative budgets, revocation,
restart, stale baseline, partial handoff and zero-work reads. macOS tests exercise
OS-level file, process and network denial including indirect effects, real
all-flow candidate success, inverse regression and correction. Unsupported OS
admission is tested explicitly; skipped OS integration is never a pass claim.

API/CLI/browser cases prove identical task ownership and retained original board
geometry/selection, visible negative results, recovery, limits and handoff.
Run focused owner tests, existing control-plane tests and seven-run proof,
static contracts, React tests, naming, lint, typecheck/build, browser tests and
inspect generated screenshots. Latest PR HEAD checks must pass before review.
