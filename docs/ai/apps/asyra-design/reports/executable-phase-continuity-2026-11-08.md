## What stopped the work

The second request re-authored the unchanged common projection and added
`kind: "bad"` beside its five legal numeric fields. This was present in the
submitted input; the delivered discovery contracts did not contain that literal.
Host admission correctly rejected the unknown field, reported not-started and
performed no second-call mutation. The existing strict evaluation then
interrupted the drawing turn. It was not a human cancellation or an AI decision
that the building was complete.

The rejection has recoverable=true but generic recovery prose, rather than the
owner-declared recovery=correct_input recognized by evaluation-control.ts. The
current evaluation consumer therefore treats it as a stopping tool failure.
That classification boundary deserves separate review if ordinary authoring
corrections should continue under strict evaluation. This run does not demonstrate
that the production App cannot recover. Do not suppress unknown failures or
silently repair authored geometry to make the benchmark finish.

The original report initially repeated the provider's generic interruption
wording. A same-thread follow-up supplied the exact collector evidence; the AI
explicitly corrected the attribution and separated input error, correct host
validation, evaluation stop and lack of a recovery opportunity.
