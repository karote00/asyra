# AI execution efficiency

Status: planned; depends on recording and precise retrieval.
Parent: [improvement plan](ai-execution-improvement-plan.md).

## Outcome

Reduce measured unnecessary preparation, communication, application and rework
without reducing requested quality, source resolution or canonical dimensions.
The App already has batch actions, deterministic patterns and computed data;
verify their actual costs before adding substitutes.

## Tasks

1. Use recording to distinguish reference acquisition, preparation, provider
   gaps, queue, creation, inspection and settlement. Preserve unknown time.
   Profile the existing bulk create path on representative repeated geometry;
   identify work counts and canonical owners behind the observed expensive
   8161-element application. Add regression tests before any confirmed fix.
2. Improve stage guidance/tool affordances: establish useful structure as soon
   as ready, validate a representative repeated visual element before expensive
   expansion when appropriate, then batch ready changes through existing tools.
   These are intent-sensitive choices, not a mandatory high-detail pipeline or
   a Taipei-specific recipe. No extra model check after every small action.
3. Audit only affected inspection dependencies. Reuse valid existing evidence;
   unknown dependencies, z-order/occlusion changes and external edits invalidate
   conservatively. Do not implement speculative target-local caching or skip
   final overall visual assessment. Avoid known full-scene response patterns
   through exact query/handle reuse from the retrieval plan.

## Completion

Every retained optimization has equivalent output and permanent work-count,
invalidation/cancellation/history tests. Preserve original editable output,
manual interaction and progressive updates. Run applicable formal bulk/7076
gates at the completed owner milestone, not after each small edit. End with the
parent plan's one successful full live recording. Report observed quality/time
without claiming causal or universal 1–2 minute performance from one sample.
If profiling does not support a suspected optimization, record evidence and keep
that owner unchanged; this is preferable to inventing a cache or renderer.
